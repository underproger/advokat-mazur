# Дизайн 3 → WordPress (advokatmazur.com.ua)

Тема `mazur/` — дизайн 3 для чинного WordPress-сайту. Контент у полях ACF, мови — **Polylang Pro 3.5.1**
(UA за замовчуванням **без префікса** — усі старі адреси не змінюються; RU — `/ru/…`).
Працює і з безкоштовним Polylang, але без можливостей Pro (див. нижче).

```
3/wp/
  mazur/                         тема (заливається як zip)
    import/content.json          контент UA+RU для імпортера (генерує 3/_build/export_wp.py)
  gtm/gtm-import-advokatmazur-goals.json   імпорт цілей у GTM-PK34TX83
```

Змінили тексти в `3/_build/data_services.py` чи перекладах → `python3 3/_build/export_wp.py` → перезалити тему →
імпорт з галочкою «Перезаписати».

## Встановлення на сайт

1. **Резервна копія** (Duplicator) — сторінки послуг оновлюються на місці.
2. Плагіни: **ACF PRO**, **Contact Form 7**, **GTM Kit** — уже стоять. Встановити й активувати **Polylang Pro**
   (zip; безкоштовний Polylang паралельно не ставити). Майстер налаштування можна пропустити — мови й URL налаштує імпортер.
   Ліцензійний ключ — Мови → Налаштування → Ліцензії (потрібен лише для оновлень).
3. Зовнішній вигляд → Теми → Додати → Завантажити `mazur.zip` → **Активувати**.
4. Одразу після цього: Інструменти → **«Мазур: імпорт контенту»** → «Імпортувати» (≈1 хв, журнал на екрані).
5. Налаштування → Постійні посилання → «Зберегти» (оновить правила URL з `/ru/`).
6. **Налаштування сайту** (пункт меню адмінки): контакти, месенджери, свідоцтво; статистика Google — лише реальні цифри.

Між кроками 3 і 4 сайт кілька секунд показує нову тему зі старим контентом — краще робити в тихий час або спершу на копії.
Повернення назад — відновлення з копії Duplicator (стару тему просто активувати недостатньо: змінено шаблони сторінок).

## Адмінка: як заповнювати

* Сторінки послуг і **головна** — усі тексти в полях ACF, вкладки за блоками сторінки в порядку виводу
  (як у старій темі: «Банер», «Як це працює», «Ситуації» … «FAQ», «Заявка»). У головної 13 вкладок.
* **Списки** (пункти під H1, ціни, «що підготувати», пункти у вкладках) — репітери: «Додати пункт», рядки перетягуються.
* **Абзаци** (вкладки «Допомога», фото-блоки, стаття, відповіді FAQ, SEO-тексти головної) — візуальний редактор.
  Посилання — кнопкою «ланцюжок» з пошуком сторінки сайту. Редактор вмикається кліком по полю (сторінка в адмінці не гальмує).
* **Іконки** — вибір із сітки з превʼю.
* **Репітери** згортаються з заголовком рядка; ліміти під верстку: ситуацій ≤ 9, вкладок ≤ 8, етапів 2–4 (головна — 6),
  фото-блоків ≤ 4, порад 4.
* Вкладка **«Секції сторінки»** — перемикачі «показувати» для кожного блоку (послуга — 12, головна — 9).
  Блоки без контенту (немає відгуків, рядків) ховаються самі.
* Порожнє поле головної → текст дизайну 3 за замовчуванням (`inc/home-defaults.php`).

## Polylang Pro: як працюють переклади

**Поля ACF** мають налаштування перекладу (у коді, `inc/acf-fields.php` → `mz_acf_pll()`):

| Поля | Режим | Що відбувається |
|---|---|---|
| Тексти верхнього рівня (H1, лід, пункти, SEO-заголовок і вступ статті, title/description…) | translate | копіюються в новий переклад, далі редагуються окремо; йдуть в експорт XLIFF |
| Фото першого екрана, пресет фото, іконка, картка «Оформлення веде адвокат», «Послуга» в кейсі, час читання | sync | однакові в UA і RU: змінили в одній мові — оновилось в іншій; «Послуга» автоматично підставляється сторінкою потрібної мови |
| Усе всередині репітерів (ситуації, вкладки, етапи, фото-блоки, відгуки, FAQ, розділи статті) | copy_once | копіюється при створенні перекладу, далі UA і RU незалежні |

Репітери навмисно не синхронізуються: інакше Polylang Pro вирівнює кількість рядків між мовами, і видалення рядка в UA
зсуває рядки в RU. Рядок без заповненого головного тексту (питання, заголовок…) на сайті не показується.

**Нова сторінка/переклад:** у списку сторінок «+» у колонці RU → Polylang Pro створює переклад і копіює всі поля → перекласти тексти.
Ключ сторінки (для посилань `{{url:ключ}}`) береться з перекладу або слагу автоматично.

**Рядки шаблонів** (кнопки, заголовки секцій, футер тощо) — Мови → **Переклади рядків**, група «Тема Мазур» (268 рядків).
RU заповнені імпортером; можна правити і RU, і UA-формулювання — без коду.

**Синхронізація** (Мови → Налаштування → Синхронізація): увімкнено порядок сторінок і шаблон сторінки — порядок послуг у меню
однаковий для мов. «Користувацькі поля» НЕ вмикайте — синхронізація ACF уже налаштована по полях.

**Слаг кейсів** перекладено: UA `/keysy/`, RU `/ru/kejsy/` (Мови → Переклади рядків → «URL slugs»).

## Заявки та аналітика

* Форми теми → **Contact Form 7** («Мазур: заявка з сайту», створює імпортер; лист на ту саму адресу, що й стара форма).
  У листі — тема, сторінка, мова і **UTM/gclid** першого заходу.
* Після відправки — перехід на `/thanks/` (RU — `/ru/spasibo/`), як на старому сайті: налаштовані на неї конверсії працюють і далі.
* GTM-PK34TX83 підключає GTM Kit (як і раніше). Мета-тег it-rating зі старої теми — у «Налаштування сайту → Коди».
* Події в `dataLayer` (assets/js/site.js):

| Подія | Коли | Параметри |
|---|---|---|
| `generate_lead` | заявку успішно відправлено | `form_location` (modal / contact / home), `form_topic`, `page_type` |
| `click_phone` | клік по номеру | `link_location` (header, footer, mobile_bar, contact…), `page_type` |
| `click_messenger` | клік Telegram / Viber / WhatsApp | `messenger`, `link_location`, `page_type` |

### GTM

1. Адміністрування → **Імпортувати контейнер** → файл `gtm/gtm-import-advokatmazur-goals.json` →
   робоча область: наявна → **Об'єднати → Перейменувати конфліктні**.
2. Змінна **«GA4 — Measurement ID»** → вписати ID потоку GA4 (`G-…`, той самий, що в тезі Google цього контейнера).
3. Попередній перегляд: відправити заявку, клікнути телефон і месенджер — мають спрацювати 3 теги «GA4 Event — …».
4. Опублікувати.

### GA4

* Адміністрування → Події → позначити **ключовими**: `generate_lead`, `click_phone`, `click_messenger`
  (з'являться в списку після перших спрацювань; або «Створити ключову подію» з цими назвами одразу).
* Спеціальні параметри (рівень події): `form_location`, `form_topic`, `messenger`, `link_location`.
* За потреби — імпорт ключових подій у Google Ads.

## Контент — що перевірити з клієнтом

* **Цифри з дизайну** повернуто: «500+ справ і проваджень», «5.0 рейтинг у Google», «48 відгуків у Google»
  (головна → «Цифри»; послуги → Налаштування сайту → «Цифри і Google»). Рейтинг і кількість мають збігатися з профілем
  у Google — додайте туди ж посилання на відгуки, тоді з'явиться кнопка «Усі відгуки в Google».
* **Відгуки** — реальні зі старого сайту: чіп-карта (6), критичність (6), на Коді 95 — відгуки водіїв про чіп-карту,
  на головній — 3 + 3. Нові додаються у вкладці «Відгуки» сторінки (рядок «Джерело»: Google / Відгук клієнта).
* **Кейси** — демо з макета, імпортовані **чернетками**. Розділ «Кейси» з'явиться в меню, щойно буде опубліковано хоч один реальний.
* **Політика конфіденційності** на сайті — чернетка; посилання на неї в футері й формах з'явиться після публікації.
* «Економічні та фінансові злочини» — сторінка є (`/ekonomichni-zlochyny/`, RU `/ru/ekonomicheskie-prestupleniya/`),
  у меню, футері, на головній; текст не з чинного сайту — потрібна вичитка адвокатом.
